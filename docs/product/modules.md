# AIELTS Together — Modules
## 1. Purpose
This document is the authoritative product specification for the functional modules of AIELTS Together.
It defines:
- What each module is responsible for.
- Which capabilities are included.
- Which capabilities are intentionally excluded.
- Important product-level constraints between modules.
Implementation architecture, database schemas, and milestone timing belong in other documents.
---
# Group A — Foundation
## 2. Authentication Module
### Responsibilities
- Register with email, username, and password.
- Login with email or username and password.
- Logout.
- Change password while logged in.
- Resolve the current user.
- Protect authenticated pages.
### Not included in the current MVP
- Email verification.
- Google login.
- Social login.
- Device management.
- Remote logout.
- Email-based password recovery.
### Product constraint
Basic session handling is required so the application can identify the current user, but advanced session-management UX is not required.
---
## 3. User Profile Module
### Profile information
- Display name.
- Avatar.
- Current band.
- Target band.
- Expected exam date.
- Weekly study-hour goal.
- Interface language.
- Timezone.
- Total XP.
- Current streak.
### Supported languages
```text
vi — Tiếng Việt
en — English
```
### Visibility rules
Other members in the same group may see:
- Name.
- Avatar.
- XP.
- Streak.
- Assignment completion status when relevant.
They must not see:
- Detailed Reading scores.
- Detailed Listening scores.
- Writing band.
- Writing content.
- Detailed personal progress reports.
---
## 4. Group Module
### Responsibilities
- Create a group.
- Edit group name and description.
- Generate invite code.
- Join by invite code.
- View members.
- Remove members.
- Leave a group.
- Transfer ownership.
- Dissolve a group.
- Manage owner, admin, and member roles.
### Owner
- Manage group information.
- Manage members.
- Create and edit study plans.
- Enable or disable leaderboard.
- Enable or disable Team Activity.
- Transfer ownership.
- Delete the group.
### Admin
- Manage study plans.
- Monitor assignment status.
- View members.
- Create manual assignments for the whole group.
### Member
- View the study schedule.
- Receive assignments.
- Complete activities.
- View member XP.
- View leaderboard.
- Send fixed reactions.
### Group structure
```text
Group
├── Overview
├── Study Plan
├── Assignments
├── Members
├── Leaderboard
└── Activity
```
### Not included
- Realtime chat.
- Free-form comments.
- Private messaging.

# Group B — Goals and Assignment Automation
## 5. Goal Module
A Goal represents the shared learning objective of a group.
### Core information
- Target band.
- Start date.
- End date.
- Status.
- Associated study plan.
### Status
```text
ACTIVE
COMPLETED
CANCELLED
```
### Product rule
A group should have at most one active goal at a time in the current MVP.
---
## 6. Study Plan Module
A Study Plan defines what the group studies and when.
### Supported schedule types
#### DAILY
Example:
```text
Every day:
- 1 Reading
- 1 Listening
```
#### WEEKLY
Allows specific weekdays.
Example:
```text
Monday:
- Writing Task 1
Thursday:
- Writing Task 2
Saturday:
- Reading
```
### Not supported
- Every N days.
- Complex recurrence.
- Different schedules per member.
- Ability-based assignment adjustment.
- Difficulty-based assignment adjustment.
### Default deadline behavior
- Assignment is created at the start of the day.
- Deadline is 23:59 on the same day.
- Late submission is allowed.
- Late work is marked accordingly.
Default initial timezone:
```text
Asia/Bangkok
```
---
## 7. Assignment Scheduler Module
The scheduler automatically creates assignments from active Study Plans.
### High-level flow
```text
Scheduler runs
      ↓
Find active Study Plans
      ↓
Determine today's required skill
      ↓
Take the next content item by sequence
      ↓
Create assignment for the whole group
      ↓
Create member notifications
```
### Content-selection rule
Content is selected strictly by sequence.
Example:
```text
Reading 001
Reading 002
Reading 003
...
```
The scheduler does not evaluate:
- Suitability.
- Difficulty.
- Topic.
- Group ability.
### When content is exhausted
- Do not loop back to the beginning.
- Stop creating assignments for that content type.
- Record an error.
- Notify the system administrator.
---
## 8. Assignment Module
An Assignment is a concrete activity assigned to a group.
### Product rules
- Every assignment applies to the entire group.
- Individual member assignments are not supported.
- Content comes from the Question Bank.
- Deadline comes from the Study Plan.
- Assignments may be automatic or manual.
- Manual assignments still apply to the whole group.
### Generated by
```text
AUTO
ADMIN
```
### Assignment status
```text
SCHEDULED
ACTIVE
CLOSED
ARCHIVED
```
### Member-level status
```text
NOT_STARTED
IN_PROGRESS
SUBMITTED
LATE
MISSED
```

# Group C — Content and Submissions
## 9. Question Bank Module
The Question Bank stores all supported learning content.
### Supported content types
- Reading.
- Listening.
- Writing Academic Task 1.
- Writing Task 2.
Speaking is not included.
### Not used for adaptive learning
The current product does not depend on:
- Topic tags.
- Difficulty.
- Personalized recommendations.
- Ability matching.
### Source tracking
Source information should be retained internally to support:
- Error correction.
- Duplicate detection.
- Crawler debugging.
- Original-source verification.
### Content status
```text
ACTIVE
DISABLED
```
A broken item can be disabled without deletion.
---
## 10. Submission Module
Submission stores user work for both individual practice and group assignments.
### Responsibilities
- Save draft.
- Auto-save.
- Submit work.
- Review submitted work.
- Store answers.
- Store score when applicable.
- Distinguish individual practice from group assignments.
### Conceptual relation
```text
assignment_id != null
→ Group assignment
assignment_id == null
→ Individual practice
```
### Submission status
```text
DRAFT
SUBMITTED
GRADED
LATE
```
Future AI-related states may include:
```text
GRADING
GRADING_FAILED
```
AI states are not required before the AI Writing capability is released.

# Group D — IELTS Skills
## 11. Reading Module
### Responsibilities
- Select Reading content for individual practice.
- Open Reading from a group assignment.
- Display passage.
- Display questions.
- Auto-save answers.
- Mark unanswered questions.
- Submit answers.
- Grade automatically.
- Show correct answers.
- Show total correct answers.
- Show reference band conversion.
- Store history.
### Priority question types
- Multiple Choice.
- True / False / Not Given.
- Yes / No / Not Given.
- Matching Headings.
- Sentence Completion.
- Short Answer.
### Result view
After submission, the module should focus on:
```text
Your answer
Correct answer
Total correct answers
Reference band
```
### Not included
- Answer explanations.
- Error analysis.
- Next-exercise recommendation.
- Question-type error profiling.
- AI passage explanation.
---
## 12. Listening Module
### Responsibilities
- Select Listening content for individual practice.
- Open Listening from a group assignment.
- Play audio.
- Display questions.
- Auto-save answers.
- Submit.
- Grade automatically.
- Show correct answers.
- Show transcript after submission when available.
- Store history.
### Not included
- Answer explanations.
- Error analysis.
- Listening-error classification.
- AI transcript analysis.
- Multi-quality streaming.
### Media principle
Audio files are external media assets referenced by content records.
The database should store metadata and URLs rather than the binary audio itself.
---
## 13. Writing Module
Writing must operate independently from AI.
### Supported task types
- Academic Task 1.
- Task 2.
### Responsibilities
- Select a Writing prompt for individual practice.
- Open Writing from a group assignment.
- Display Task 1 image when required.
- Provide text editor.
- Count words.
- Auto-save.
- Save draft.
- Submit.
- Review previous submissions.
- Store Writing history.
### No mandatory timer
Writing is treated as a study activity rather than a strict exam simulator.
Users may:
- Consult materials.
- Write in multiple sessions.
- Leave and return.
- Submit when complete.
### Task independence
```text
Task 1 → separate submission
Task 2 → separate submission
```
Users are not required to complete both in one sitting.
### Supported modes
```text
Question Bank
    ↓
Individual Writing
```
and:
```text
Assignment
    ↓
Group Writing
    ↓
Submission
    ↓
Group progress update
```
### Not included
- Version comparison.
- Peer review.
- Public Writing content.
- Mandatory AI grading.
- Dedicated timed exam mode.

# Group E — AI and Machine Learning
## 14. AI Writing Evaluation Module
AI is used only for Writing evaluation.
### Not used for
- Reading.
- Listening.
- Study-plan generation.
- Question generation.
- Gamification.
- General progress analysis.
### Release principle
AI Writing Evaluation is not required for the first MVP.
Writing must remain complete without AI.
### Research direction
The AI branch is also intended as a machine-learning learning and experimentation track.
Expected dataset fields may include:
```text
Prompt
Essay
Task type
Overall band
Task Achievement / Task Response
Coherence and Cohesion
Lexical Resource
Grammatical Range and Accuracy
Feedback
```
### Evaluation direction
The project may progress through:
- Dataset construction.
- Baseline machine learning.
- Deep-learning experiments.
- Structured feedback generation.
Exact model selection belongs in AI architecture and research documentation.
### Output principle
AI results should be presented as:
```text
AI-estimated band
Band ước tính từ AI
```
They must not be represented as official IELTS results.

---
## 16. Gamification Module
### Components
- XP.
- Streak.
- Badges.
- On-time completion rewards.
- Progress milestones.
- Group achievements.
### Principle
XP rules are fixed by the system and are not customizable by group owners or admins.
### Reward philosophy
Reward:
- Consistency.
- Completion.
- On-time participation.
Do not primarily reward:
- High IELTS band.
- Being first in the group.
### Basic badges
Examples include First Assignment, 7-Day Streak, 30-Day Streak, First Reading, First Listening, First Writing, Perfect Week, and Quarter Finisher.
---
## 17. Quarterly Leaderboard Module
Leaderboard uses XP earned within each quarter.
### Rules
- Historical XP is not deleted.
- Every quarter has a separate ranking.
- Previous quarters remain viewable.
- Lifetime XP remains on the personal profile.
- Only XP earned in a group counts toward that group's leaderboard.
### Display
```text
Rank
Name
Quarter XP
Streak
```
Detailed IELTS scores are not shown.
---

# Group H — Operations, Data, and Storage
## 21. Content Import Pipeline
Learning content is collected externally and normalized before database import.
### Flow
```text
Crawler
    ↓
Raw Data
    ↓
Normalizer
    ↓
Validator
    ↓
Normalized JSON
    ↓
Import Script
    ↓
Database
```
### Product rule
Crawler output must not write directly into the main application database.
The import process is responsible for validation and persistence.
### Validation examples
- Missing passage.
- Missing questions.
- Missing answers.
- Duplicate sequence number.
- Duplicate source URL.
- Invalid question type.
- Missing audio.
- Missing image.
- Invalid JSON schema.
- Question/answer count mismatch.

## 23. File & Media Storage Module
### Managed asset types
Listening audio, Writing Task 1 images, Reading images, avatars, and temporary crawler files.
### PDF principle
PDF is treated as an ingestion source, not an end-user exercise format.
After parsing, relevant content should become structured application data.
---
# 24. Explicitly Removed Capabilities
The current scope intentionally excludes: Speaking, Peer Review, Vocabulary, Error Review, Realtime Chat, free-form comments, private messages, Google Login, Email Verification, email-based password recovery, AI Reading, AI Listening, AI study-plan generation, AI question generation, Reading answer explanations, Listening error analysis, Writing version comparison, individual assignments inside a group, every-N-days scheduling, topic/difficulty-based recommendations, custom XP rules, public detailed academic results, and dedicated exam mode.
These exclusions are product decisions, not unfinished implementation tasks.
